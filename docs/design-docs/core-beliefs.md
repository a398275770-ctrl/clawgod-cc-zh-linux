# 核心信念（智能体优先的操作原则）

> 这是**争议的裁决依据**。出现"该不该这么做"的分歧时，回到这份文件，而不是回到聊天记录。
> 通用原则源自《Harness engineering: leveraging Codex in an agent-first world》（2026-02-11，OpenAI），本项目特有条目为改造与维护中沉淀的裁决。

## 通用原则

1. 人类掌舵，智能体执行。人类不直接贡献代码行。
2. 工程师的工作是设计环境、明确意图、构建反馈回路。
3. 上下文是稀缺资源；给地图，不给说明书。
4. 智能体在运行时看不到的东西，对它来说不存在。
5. 强制不变量，不微观管理实现。
6. 中央强制边界，本地允许自主表达。
7. 纠错成本低，等待成本高。
8. 技术债是高息贷款，小额高频偿还。
9. 遇到卡点先问："缺的是什么能力？如何让它既清晰可读又可强制执行？"
10. 人类品味要持续被捕捉——写进文档，或直接编码进工具。
11. 交互式决策必须落盘：确认过但不写进仓库的决策等于没做。
12. 改造存量项目时，重构不改变业务行为；行为变更必须显式登记并单独提交。

## 本项目特有裁决

13. **零 npm 依赖是特性，不是缺陷**（2026-10-12 D2）。不引入 `package.json`；lint、覆盖率、检查工具一律用 Node 内置能力自研。新增任何外部依赖必须先推翻本条并记录理由。
14. **翻译数据单一数据源**。`verbs/zh-CN.json`、`tips/zh-CN.json`、`cli-translations.json` 之外不允许出现第二份手写译文副本；派生配置现场组装，不预生成。
15. **`plugin/` 是负载副本，不是第二源码树**。只由 `sync-payload.sh` 从根复制；改 `plugin/` 副本的提交一律打回。
16. **sh/ps1 双实现是有意冗余**（2026-10-12 D3）。不为消除重复而合并；代价用「改动必须成对」的机械检查对冲。
17. **Patch 的第一优先级是"CLI 永远可用"**。汉化是增强，英文是可接受的降级态；任何 patch 失败路径都必须回滚到英文可用，不允许留下损坏的 CLI。
18. **Hook 等技术术语保留英文**。Hook、API、PR 等不翻译；追求准确优先于追求全中文化。
19. **对上游版本诚实**。未验证的版本窗口如实标注"未验证/本机自验证"，不夸大支持范围（见 README 与 support-matrix 的措辞约定）。
20. **跳过与豁免必须显式登记**：测试跳过、门禁豁免都要带原因与恢复条件（2026-10-12 D5），不允许静默跳过。
